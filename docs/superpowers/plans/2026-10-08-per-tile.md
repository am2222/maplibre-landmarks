# Per-Tile Pipelines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trees, water, roofs and landmark replacement process each tile once on arrival and keep the result until the tile goes, instead of re-reading all loaded tiles on every update.

**Architecture:** A shared `TileFeed` turns MapLibre's per-tile `sourcedata` events into `onTile(key, features)` / `onDrop(key)` callbacks (fast path: the event's tile object; fallback: the public `querySourceFeatures` grouped by tile). Each layer moves its per-update work into small per-tile stores (pure, unit-tested) and keeps only selection/budgeting in `update`.

**Tech Stack:** TypeScript, MapLibre GL JS 6.13, three.js 0.186, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-08-per-tile-design.md`

## Global Constraints

- Branch `refactor/per-tile` in the main checkout; **never commit** (the user commits).
- Tile keys: canonical `z/x/y` of the data tile. Departure rule: after the camera settles, drop held tiles outside the view bounds padded by one tile, and drop a parent tile once all four children are held (recursively). Cap 256 held tiles, farthest dropped first.
- Fast path uses `event.tile.querySourceFeatures(result, { sourceLayer, filter })`; features carry `tile: {z,x,y}`. Fallback: `map.querySourceFeatures` grouped by `feature.tile ?? {_z,_x,_y}`, else one pseudo-tile `*`.
- Visual results unchanged except: trees' mapped-tree skip is per piece.
- Existing public options and behaviour (exemptions, wall shortening, budgets, thinning, grow, theme) keep working; all current tests keep passing (update their fakes only where they assumed whole-view queries).
- Performance target: no long task over 50 ms during the Eiffel orbit / pitch-85 pan once tiles are loaded.

## Review Focus

1. A tile reloading (same key arriving again): results replaced, not duplicated. Test in Task 1.
2. Parent and child tiles held together while children load: no doubled trees/water/roofs. Test in Task 1 (drop rule) and Task 2 (tree keys deduped).
3. A building or lake split across two tiles, one arriving much later. Tests in Tasks 3 and 4.
4. A landmark model loading after its tiles are already held. Test in Task 5.
5. Style swap with the feeds alive: everything dropped, rebuilt as tiles arrive, no errors. Test in Task 1 (`reset`) and the layers' styleChanged tests.

### Task 1: `TileFeed`

**Files:** Create `src/core/tileFeed.ts`; Test `tests/unit/tileFeed.test.ts`.

**Interfaces — Produces:**
```ts
export interface FeedFeature { id?: number | string | null; geometry: { type: string; coordinates: unknown }; properties?: Record<string, unknown> | null; tile?: { z: number; x: number; y: number } }
export interface TileFeedOptions { source: string; sourceLayer?: string; filter?: unknown[]; onTile(key: string, features: FeedFeature[]): void; onDrop(key: string): void; maxTiles?: number }
export type FeedMap = Pick<MlMap, 'on' | 'off' | 'getSource' | 'querySourceFeatures' | 'getBounds'>;
export class TileFeed {
  constructor(map: FeedMap, options: TileFeedOptions);
  keys(): string[];
  featuresOf(key: string): FeedFeature[] | undefined;
  settle(): void;          // camera settled: departures (called by the owning module's update)
  reset(): void;           // style swap: drop all
  dispose(): void;
  readonly fastPath: boolean; // true once a tile arrived through the event's tile object
}
export const tileKey: (t: { z: number; x: number; y: number }) => string;
export function tileBounds(key: string): [number, number, number, number]; // lng/lat
```

- [ ] **Step 1: Failing tests** (`tests/unit/tileFeed.test.ts`), with a fake map (`on/off` storing handlers, `getSource` returning `{ maxzoom: 15 }`, `getBounds` returning a settable box, `querySourceFeatures` spy) and fake tiles `{ tileID: { canonical: { z, x, y } }, querySourceFeatures(result, params) { result.push(...features) } }`:
  - arrival via `sourcedata` `{ sourceId, tile }` calls `onTile('15/x/y', features)` once, passing `{ sourceLayer, filter }` to the tile; events for other sources are ignored; `fastPath` becomes true;
  - the same key arriving again calls `onDrop` then `onTile` (reload);
  - overscaled: two events whose tiles share a canonical id produce one key;
  - `settle()` drops held tiles outside the view bounds padded by one tile, and a parent `14/a/b` once its four children `15/2a..2a+1/2b..2b+1` are held, but keeps it while one child is missing;
  - `featuresOf(key)` re-queries the held tile object; `undefined` after drop;
  - `reset()` drops everything; `dispose()` removes the listener;
  - fallback: an event without `tile` → `settle()` runs `map.querySourceFeatures` once, groups by `feature.tile`, calls `onTile` for new keys and `onDrop` for vanished ones; features without tile info → one key `*`.
